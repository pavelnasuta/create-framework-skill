# E — Elaboration (Детализация)

**Цель этапа:** быстро проверять гипотезы с помощью AI и No-Code, переводя инсайты из R в конкретные, проверяемые решения.

**Входные данные (обязательные):** артефакты C + R (Pain Points, Archetypes, Emotional Problem).
**Артефакты этапа:** JTBD · AI-Powered Prototypes · AARRR-моделирование · MVP Concept

---

## Prompt E1 — Jobs to be Done (улучшенный)

**Роль:** Ты — продуктовый дизайнер, погружённый в контекст (C) и инсайты (R). Формулируешь JTBD и генерируешь идеи решений.

**Входные данные:**
1. **Контекст (C):** [ВСТАВИТЬ]
2. **Из R:** Pain Points [ВСТАВИТЬ] · Archetypes [ВСТАВИТЬ] · Emotional Problem [ВСТАВИТЬ]

**Инструкция:**
1. Сформулируй **3–5 JTBD** в формате: «Когда [ситуация], я хочу [мотивация], чтобы [результат]».
2. Для каждой JTBD сгенерируй **5–7 идей** функционала/решений, соответствующих Core Values.
3. Отбраковывай идеи, противоречащие ценностям.

**Формат выхода:**
```
JTBD 1: [формулировка]
  Идеи:
  - [идея 1]
  - [идея 2] ...
```
(повторить для каждой JTBD)

**Критерии качества:** JTBD описывают *задачу пользователя*, а не фичу продукта; идеи реалистичны и ценностно-согласованы.

---

## Prompt E2 — AI-Powered Prototyping + AARRR (улучшенный)

**Роль:** Ты — продуктовый дизайнер и аналитик роста. Создаёшь прототипы и моделируешь воронку.

**Входные данные:**
1. **Контекст (C):** [ВСТАВИТЬ]
2. **JTBD + идеи:** [ВСТАВИТЬ из E1]

**Инструкция:**
1. **Прототипы:** выбери 1 ключевую JTBD. Сгенерируй 3–5 вариантов сценариев взаимодействия и макетов экранов (опиши текстом: онбординг, основной экран). Каждый вариант — отдельная гипотеза UX.
2. **AARRR-моделирование:** построй воронку Acquisition → Activation → Retention → Referral → Revenue. Для каждого шага: гипотеза конверсии, механика удержания, реферальный механизм. Заложи точки измерения.

**Формат выхода:** описание 3–5 прототипов · таблица AARRR с конверсиями и механиками.

**Критерии качества:** прототипы различаются по гипотезе (а не косметикой); AARRR-конверсии обоснованы, а не взяты с потолка (пиши логику оценки).

---

## Prompt E3 — MVP Concept (улучшенный)

**Роль:** Ты — продакт, у которого есть JTBD, идеи и AARRR. Разрабатываешь концепцию MVP.

**Входные данные:**
1. **Контекст (C):** [ВСТАВИТЬ]
2. **JTBD + идеи:** [ВСТАВИТЬ из E1]
3. **AARRR:** [ВСТАВИТЬ из E2]

**Инструкция:**
1. Опиши **MVP**, сфокусированный на ОДНОЙ самой важной JTBD, где **AI — ключевой элемент**. Без AI продукт не работает.
2. Определи **ключевые метрики** валидации гипотезы (что считаем «успехом» MVP).
3. Предложи **No-Code платформы/инструменты** для реализации (Bubble, Adalo, Webflow, Make, n8n, Retool и т.п.) с обоснованием.

**Формат выхода:** описание MVP · список метрик валидации · рекомендация инструментов.

**Критерии качества:** MVP минимален, но проверяет реальную гипотезу ценности; AI — ядро, а не декорация; метрики измеримы за короткий срок.

---

**Результат этапа E:** чёткие задачи и гипотезы для тестирования, концепция MVP, прогноз воронки. Передавай в A: JTBD, MVP concept, AARRR, результаты R (конкуренты, ингредиенты/данные).
